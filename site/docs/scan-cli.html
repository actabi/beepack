Scan via CLI

Put the scanner in a pre-install hook, a CI pipeline, or a git hook.

Install

npm install -g @actabi/beepack
# or run without install
npx @actabi/beepack scan <url-or-path>

The CLI points at https://beepack.ai/api/v1 by default. Override with BEEPACK_API to hit a self-hosted instance.

Usage

beepack scan <url-or-path> [--json] [--strict]

Arguments

  • <url-or-path>: a URL (GitHub repo, blob, gist, raw) or a local path. If you pass a directory, the CLI looks for SKILL.md at the root and picks up same-directory scripts (.sh, .py, .js, .ts). If you pass a single file, only that file is scanned.

Flags

  • --json: emit the raw scan JSON instead of the human-readable summary. Useful for piping into jq or storing in CI artifacts.
  • --strict: treat YELLOW as a failure. Exit code becomes 2 instead of 1.

Exit codes

CodeMeaning
0GREEN: scan succeeded, no issues.
1YELLOW: warnings. Becomes 2 under --strict.
2RED: at least one blocking issue.
3Network or fetch error. The scan did not complete.

Examples

Scan a GitHub repo

beepack scan https://github.com/anthropics/skills

Scan a local folder before running an AI-generated installer

beepack scan ./my-skill/ && ./my-skill/install.sh

Because beepack scan exits non-zero on RED, the && short-circuits if the skill is unsafe.

Fail CI on any warning

beepack scan ./skill --strict

Pipe into jq

beepack scan https://github.com/owner/repo --json | jq '.findings[] | select(.severity=="block")'

Pre-install hook template

Drop this into ~/.bashrc or ~/.zshrc if you want every npx to be scanned when the source is a GitHub URL:

safe_install() {
  local url="$1"
  beepack scan "$url" >/dev/null 2>&1
  local rc=$?
  if [ $rc -ne 0 ]; then
    echo "refusing to run: beepack scan returned $rc for $url"
    return $rc
  fi
  shift
  "$@"
}

# Usage:
# safe_install https://github.com/owner/repo bash install.sh

Point at a self-hosted instance

BEEPACK_API=https://scan.my-company.com/api/v1 beepack scan <url>
