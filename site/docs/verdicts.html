Verdicts and findings

Every rule the scanner applies, what triggers it, and how to read the output.

Verdict logic

The verdict is computed from the findings list, in order:

  1. RED if any finding has severity: "block".
  2. YELLOW else if any finding has severity: "warn".
  3. GREEN otherwise.

The aggregator does not weight findings. One block is enough to flip the verdict to RED; a dozen warn findings stay YELLOW.

Finding types

package_does_not_exist BLOCK

An npm (or pypi, when enabled) package referenced in the skill returns HTTP 404 from the registry. Classic hallucination: the LLM invented a plausible-looking name, the package has no real owner, and a typosquatter can claim it.

Example triggers: npx @anthropic/skill-runner-plus, pip install reqeusts-utils.

possible_typosquat (distance 1) BLOCK

Levenshtein distance of 1 from a package in the top 5,000 npm or top 1,000 PyPI list, AND the candidate itself is not in the top list. Distance 1 means a single insertion, deletion, or substitution, which is the signature of deliberate squatting.

Example triggers: expresss (vs express), reqeusts (vs requests), stripe-cli (vs stripe when -cli is flagged separately).

possible_typosquat (distance 2) WARN

Same rule, distance 2. Still suspicious but more prone to false positives, so it warns instead of blocks. Confidence field in the finding is 0.75 for distance 2.

possible_typosquat (suspicious suffix) WARN

Candidate has a known trailing suffix (-js, .js, -cli, -py, -python, -pkg, -core, -lib) and the stem without the suffix is in the top list. These are legitimately used (e.g. stripe-js as a real mirror), so we warn rather than block.

urlhaus_match BLOCK

A URL in the skill (or inside a curl/wget command) matches an entry on the URLhaus blocklist (abuse.ch). We check both full-URL matches and host-only matches. The blocklist is refreshed daily and contains ~25,000 known-bad URLs.

pastebin_or_tunnel WARN

URL uses a pastebin service (pastebin.com, hastebin.com, paste.ee, transfer.sh, catbox.moe, etc.) or a tunneling service (ngrok.io, trycloudflare.com, loca.lt, serveo.net). Legitimate use exists, but these hosts are disproportionately used for one-shot payload delivery and data exfiltration, so we warn.

young_domain WARN

The URL's registrable domain was registered under 30 days ago, per RDAP (rdap.org). Young domains are used by a disproportionate share of phishing and malware campaigns. Legitimate products do ship on fresh domains, so it warns.

nothing_to_scan WARN

The skill has no detectable shell commands, URLs, or package references. This can mean two things: the skill is trivial (just prose), or the parser missed something. We flag it so you don't assume GREEN means "checked thoroughly" when in fact there was nothing to check.

invalid_url WARN

The skill contains a URL-like string that failed to parse. Rare, but flagged because malformed URLs sometimes indicate obfuscation.

Reading a finding

{
  "severity": "block",
  "type": "possible_typosquat",
  "ecosystem": "npm",
  "package": "expresss",
  "likelyTarget": "express",
  "distance": 1,
  "confidence": 0.95,
  "message": "\"expresss\" looks like \"express\" (distance 1, levenshtein)",
  "locations": [
    { "source": "SKILL.md", "line": 12, "reason": "npm install" }
  ]
}
  • severity: block or warn.
  • type: the finding type (see sections above).
  • message: one-line human summary.
  • locations: array of {source, line, reason} pointing at every place the issue appears.

False positives

The ruleset leans conservative. If you believe a finding is wrong:

  • Open an issue at github.com/actabi/beepack/issues with the scan ID and a one-line explanation.
  • Likely targets for tuning: possible_typosquat distance-2 false positives, pastebin hosts used by legitimate tooling.

What we deliberately do not check

See the introduction for the full non-goals list. Short version: we validate references against public data sources. We do not perform LLM-based code review, and we do not attempt semantic understanding of what the skill does. That is by design: the scanner's value is being deterministic and cheap to run.
