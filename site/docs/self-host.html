Self-hosting

Run the scanner on your own machine or VPS. Node 20 plus SQLite, nothing else. MIT licensed.

Requirements

  • Node.js 20 or newer (uses fetch, AbortController, test runner).
  • SQLite via better-sqlite3 (installed by npm).
  • Outbound HTTPS to registry.npmjs.org, api.npmjs.org, rdap.org, urlhaus.abuse.ch, data.jsdelivr.com, hugovk.github.io, and api.github.com (for URL-based scan inputs).

Clone and run

git clone https://github.com/actabi/beepack.git
cd beepack
npm install
node server.js

Default port is 3011. Override with PORT=8080 node server.js.

Populate the offline data

The typosquat detector and URLhaus check both rely on local data files. The scanner boots fine without them, but typosquat detection silently becomes a no-op and URLhaus matching is disabled. Populate them once, then refresh on a cron.

# Weekly (or on deploy)
node scripts/fetch-top-packages.js
# Daily (or on deploy)
node scripts/fetch-urlhaus.js

Files land at data/npm-top.txt, data/pypi-top.txt, data/urlhaus.csv. The scanner picks them up on server restart.

Tune list sizes

NPM_TOP_N=10000 node scripts/fetch-top-packages.js --npm-only
PYPI_TOP_N=2000 node scripts/fetch-top-packages.js --pypi-only

Higher N means better typosquat coverage but more false positives and larger files. The public instance runs with 5000 npm and 1000 pypi.

Cron template (Linux)

# crontab -e
0 3 * * 0 cd /opt/beepack && node scripts/fetch-top-packages.js && systemctl restart beepack
15 3 * * * cd /opt/beepack && node scripts/fetch-urlhaus.js  && systemctl restart beepack

Daily digest

node scripts/scan-daily-report.js --save --mail

Prints a plaintext digest (total scans, verdict mix, top sources), optionally saves it to data/reports/YYYY-MM-DD.json, and optionally pipes it to sendmail -t. Wire into cron for an 08:00 UTC email.

Point the CLI at your instance

BEEPACK_API=https://scan.internal.example.com/api/v1 beepack scan <url>

No authentication is required on the public instance. If you add auth to your fork, the CLI does not yet support bearer tokens; contributions welcome.

Hardening checklist

  • Set a unique SCAN_IP_SALT in prod. The default salt leaks in source.
  • Put the server behind Caddy or nginx with HTTPS. The binary speaks plain HTTP.
  • Adjust the rate limit in server.js (scanLimiter) if you expect higher volumes. Default is 30 scans per minute per IP.
  • Back up data/beepack.db periodically. Scan history lives there; loss is not catastrophic but ID links break.
  • Keep the data fetchers on cron. Stale urlhaus.csv and top-lists are the fastest path to false negatives.

Where the code lives

  • skill-parser.js: deterministic extractor (shell commands, URLs, packages, imports).
  • validators/npm.js: npm registry calls, cached.
  • validators/typosquat.js: Levenshtein + suffix rules.
  • validators/urls.js: URLhaus, RDAP, pastebin/tunnel lists.
  • verdict-aggregator.js: pure aggregation logic.
  • scan-engine.js: orchestration.
  • scan-store.js: SQLite persistence.
  • server.js: HTTP surface (POST /api/v1/scan et al.).
  • cli/src/scan.js: CLI.
  • site/scan.html, site/index.html: UI.

Tests: node --test tests/. The scanner suite is 77 tests across 8 files, all under 1s total.
