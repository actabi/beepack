What's actually in the library

Each package exists because a frontier LLM reliably hallucinates this API. We do not duplicate what Claude or GPT already generate well.

🏢

SIRET / SIREN validation

Luhn checksum for 14-digit SIRET and 9-digit SIREN, with proper formatting. French-only, zero deps.

beepack pull siret-utils
🧹

CDN URL cleaner

Extract the original image behind Wix, Shopify, WordPress, Squarespace transformed URLs. Domain heuristics LLMs don't know.

beepack pull cdn-url-cleaner
🌐

CMS detector

Identify CMS, JS framework, analytics, and server stack from any URL. Heuristic signatures, not just headers.

beepack pull cms-detector
🔒

Auth.js v5 (NextAuth) setup

Production config for the v5 rewrite LLMs still emit v4 patterns for. GitHub, Google, magic-link, App Router.

beepack pull nextauth-setup
📋

Linear API client

GraphQL issue CRUD, webhooks, projects, comments. Recent schema changes LLMs get wrong.

beepack pull linear-api

Why this, instead of just asking Claude?

For 90% of APIs, frontier LLMs do fine. This library only covers the other 10%.

Scenario Ask Claude directly Use Beepack
Stripe checkout handler ✓ Claude does fine ✗ We don't cover this
Standard OAuth flow ✓ Claude does fine ✗ We don't cover this
SIRET Luhn validation ✗ Often wrong digit weights ✓ Tested Luhn impl
Auth.js v5 (v4→v5 migration) ✗ Still emits v4 patterns ✓ v5-native
Wix / Shopify CDN URL parsing ✗ Hallucinates paths ✓ Domain heuristics
French regulatory (URSSAF, Pappers) ✗ Invents endpoints ✓ On the niche roadmap
